the number that survived two transactions

two writes, one read, the value held

counter — anvil / cast session
// deployed, fresh slot   number = 0
cast send increment() # tx #1, own block  →  number = 1
→ a transaction, its own block
Between the two sends: separate transactions, separate blocks — nothing in your shell remembered the first one.
cast send increment() # tx #2, own block  →  number = 2
→ a second, independent transaction
cast call number() // read-only  →  returns 2
read back from chain state — the value was waiting for you
Two writes in two transactions, one read minutes later — and the value held. State lives in the contract, not the process.
