token-engineer
¿Los sellos como token en la billetera del cliente?
Las mínimas extensiones que hagan el trabajo. Cada una reduce dónde puede operarse el token, y el conjunto se fija al crearlo.
Para sellos: Token-2022, non-transferable más extensión de metadata, tienda como autoridad del mint, un café gratis es un burn.
La ATA se deriva del program id de Token-2022. El id clásico da la dirección equivocada.
metaplex para NFTs · /inspect-mint lee cualquier mint
defi-engineer
¿El cliente paga con cualquier token?
Output mínimo exigido on-chain. Recarga el destino tras el swap y revisa el delta del saldo, nunca la cotización.
Precio de un oráculo con feed id y antigüedad máxima, no de reservas spot que un flash loan puede mover.
Jupiter swap v2 con API key. Prueba en un fork de mainnet con Surfpool: cargan las cuentas reales del protocolo.
jupiter · sendai para lending y oráculos
game-architect → unity-engineer
¿La tarjeta como juego?
On-chain lo que es valioso, intercambiable o confiado por otros jugadores. Jugabilidad off-chain, escrita en checkpoints.
Los puntajes que reporta el cliente los controla el atacante: un pago se verifica on-chain o con firma del servidor.
concept.md en números, plan.md en pasos, tu aprobación, después Unity en pasos pequeños cerrando con /build-unity y /test-dotnet.
