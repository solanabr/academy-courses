Four things that keep you good at this

solana-guide
Checks your level first. Definition, the problem it solves, a minimal example, the beginner's mistake, then asks you to predict before moving on. Draws Mermaid when accounts, PDAs and CPIs interact. Teaches current tooling and names a tutorial that predates it.
Learning only. Production code goes to the engineers.
/explain-code
Overview in two or three sentences, a Mermaid diagram, a walkthrough of the significant sections with the reasons, the Solana concepts used, security notes on checks performed and checks missing, and two or three what-happens-if questions.
Run it on the code the engineers wrote for you.
solana-researcher, as a habit
Before building on a program: upgrade authority, verified build, audit history, cited and dated. Before any decision that depends on a version or a status: ask it, not memory.
