The four firewall tiers

TierWhat the agent can readAn on-chain writeUse it for
OffEverything your user account can. The sandbox is off.No stop from the kit's hooks. Still refused: --final, program close, authority disable, the never-allowed deny rules, a recursive rm at a root, kill -1.A machine you already isolated: a container or a throwaway VM.
Relaxed
default		The repo and your toolchain. Solana config dir except the default wallet, the project's .env. Denied: wallet file, SSH and GPG keys, tokens, keychains, browser profiles, shell history.Stops for your approval on every cluster except a local validator, naming the cluster.Local development on your own machine and your own repo. The tier to run headless.
MediumRelaxed's denials plus the wallet JSON files and session transcripts. .env becomes write-denied.As Relaxed. Publishing and force pushes ask or are denied; writes to a local validator ask.Reading code you did not write: audits, a cloned repo. Interactive only.
HighOnly the working directory and the toolchain roots. .env is read-denied, even for a build.Mainnet writes denied outright. The only tier that stops the agent editing the kit's own config.A repo you distrust, or a machine holding production credentials. Interactive only.
At every tier: the guard scripts in .claude/hooks/ are denied to the agent, and a nested Claude Code with a policy-weakening flag is refused.
safe-ai-skill refuses .env to the file tools and cat-style reads at every tier while it is on, and gates mainnet, authority and value-moving actions in Bash and in MCP tools.
A switch applies next session. /firewall <tier> rewrites the rules now; the session you are in keeps the ones it started with.
